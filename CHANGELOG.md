## 0.7.2 (prepared 2026-10-25; on top of 0.7.1)

C336 RQ-3, C330(3), C325: the Knowledge app gets a grant from Connect to tap directly into a supported data source. Postgres first (MySQL is the next kind: one driver and one query set, see `src/data/database.ts`).
- **Database accounts:** the owner adds a Postgres database (Accounts > Databases, person op `database_account_connect`): host, port, database, user, password, sslmode. The DSN is sealed in Connect (`ctx.secrets`), never in the database file. The host goes through the same public-address policy as catalog and MCP URLs (a private address, a local name or a mixed DNS answer is refused; no owner exception exists, C41). Connect connects once and refuses a superuser or a replication role. The form recommends a dedicated read-only user with SELECT only and no REPLICATION. Agents never see a database account.
- **Sharing:** `account_app_share` now also shares a database with Knowledge or Observer at `available` (table list only) or `shared` (lease), with a `route`: `direct` (default; the app may lease) or `via_observer` (only Observer reads it; Knowledge gets nothing for it: not listed, `not_found`). Changing or ending a share ends its open leases.
- **`data_catalog` of a database:** schema.table, table or view, columns with types, approximate rows (statistics, `pg_class.reltuples`). Never a value. Connect sends only fixed metadata statements (`POSTGRES_SQL` in `src/data/database.ts`).
- **New op `data_lease`** (apps only, level `shared`, route `direct`): `{account, datasets[1..50] as schema.table, ttlS <= 900}` answers `{leaseId, kind, host, port, checkedAddress, database, user, password, sslmode, datasets, expiresAt}`. Only datasets in the catalog now. `checkedAddress` is the address the policy checked at the lease; connect to it with TLS name `host`. v0 lease = the owner's sealed read-only credential plus an expiry that Connect records (no per-lease database role yet): ending a lease marks it ended in Connect, the password stays valid at the database until the owner changes it there. The password is in the op output only: not in the lease record, the audit line, the access log, the owner lists, receipts, log lines or error texts (canary test). The op follows spec 0.1.68 M-OP-12 (QA change of specs#47): read, idempotency none, agent audience, not dynamic, and `receipt: true` (the receipt keeps the input digest and a redacted summary: app, number of tables, database label, end time; never the answer). Every error on the lease path has a code and a fixed message (no host, user, password or DSN text). The `secretOutput` flag is NOT in the manifest because the pinned manifest schema (spec 0.1.52) refuses the unknown field; when the pin moves, add it and use the spec code `secret_output_app_only` for the refusal of a non-app caller (today `no_access`, like the other data ops).
- **Owner ops:** `data_leases_list` (no secrets), `data_lease_revoke` (receipt). The access log (`data_access_log`) names the lease, its end and the tables.
- **Migration 0018 (expand only; follows 0016 channel actions and 0017 Buzz actions):** tables `connect_db_accounts`, `connect_db_shares` (with `route`), `connect_data_leases`; nullable audit columns `lease_id`, `lease_expires_at`. New tables, not a new `connect_accounts.source` value: that column has a CHECK list and SQLite can only widen it by rebuilding the table, which would cascade-delete child rows while foreign keys are on.
- **C354 tool names:** `toolName()` (`src/tools.ts`) drops the underscore at the cut before it appends `_<hash>`, so a shortened catalog entry name never contains `__` (`x__<suffix>` is reserved for resolved variants such as `__first_contact`); it also refuses a name with `__`. Existing names are unchanged unless their 39th character was an underscore.
- **Dependency:** `pg` 8.23.1 (MIT; `src/data/pg-driver.ts`) with `@types/pg`; no test opens a connection (an injected fake driver).

### Changed
- `channel_reply` to a message that was deleted answers 404 `channel_message_unknown` (a deleted message is no longer in the agent inbox). Accepted.
- `channel_inbox` returns a `nextSeq` that moves past rows it hides (deleted messages, other bots' messages), so the next call does not scan them again.
- Disconnecting an account removes its app shares.
- `channel_inbox` (agents) no longer lists a message that the provider deleted.
- Dependencies: manifest 0.1.19 (was 0.1.18; `validateAgainstSchema`, `normalizeHandle`); miniapp-sdk, spec, conformance and ui unchanged. Lockfile integrity re-pinned.

### History in this phase
- No provider has a history reader in Connect yet. The inbound log (kept 30 days; apps need at least 7) is the only record. `data_catalog` says `history: false` for Slack, Teams, Telegram and Discord, and a backward pull answers `exhausted: true` with no rows. A forward pull from the start returns everything the log holds. Telegram bots are live-only.
- Attachment metadata is supported by the log and the contract, but no inbound parser fills it yet.
- Buzz is not a connected account and is not part of the dataset in this phase.

### Gaps
- Calls the SDK itself rejects (bad grant, `grant_invalid` on a `prd`/slice mismatch, paused, stale slice) never reach a handler, so they are not in the access list. By design.
